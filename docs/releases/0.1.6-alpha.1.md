# Hexbot 0.1.6-alpha.1

Planned next alpha after 0.1.5-alpha.1. Not published.

## Changes

- Hexbot now ships a native daemon and a bundled agent runtime. Each section
  keeps its own persistent conversation. Your bots, rooms, memory and existing
  history stay in the same home directory.
- Full packages include the daemon, web assets and bundled skills. First launch
  installs Python for code tools and voice tools through a pinned,
  checksum-verified installer. Client-only packages still install no daemon.
- Runtime updates keep the active version and its predecessor. Older files are
  removed after activation, while files used by a running daemon are protected.
- Existing background services can move to the native daemon through their
  usual update action. The app also updates old service definitions when opened.
  Hexbot refuses to start a second daemon while the old one still holds its home.

- New sections reach connected tools through Pi's built-in MCP and codemode.
  Manual and Auto ask before tools that are not marked read-only; Allow in this
  section covers the server. Bypass runs without asking. Connection failures
  appear under the conversation header. Saved sections keep their existing tools.
- New connected servers accept stdio or streamable HTTP. New SSE entries are
  rejected, and existing SSE servers are skipped in new sections with a notice.
- Stdio servers now start in the bot workspace and inherit only Pi's allowlisted
  environment plus their own `env`. Add explicit environment references for any
  connector credentials a server needs. Previously it inherited all of them.
- Connected server tool counts show the last probe result, or Not tested.

## Upgrading

Back up your Hexbot home before upgrading. Existing background services retain
one release of compatibility with their previous update feed. After handoff,
Hexbot removes the old Python environment and source copies. A small forwarding
script may remain until the app reloads an old background service.

Python daemon rollback builds are removed. New conversations are stored by the
native daemon and are not copied back into the former backend's history.

## Known gaps

Native update archives are checked against SHA-256 over HTTPS. Independent
manifest signatures are planned for a follow-up release.
